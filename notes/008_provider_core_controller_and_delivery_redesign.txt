SECS: adopt the shared Attempt controller and result delivery
===========================================================
2026-10-28

Status and decision
-------------------

This note defines the intended redesign, not an implemented migration or a
deployment instruction. Adopt provider-core's AttemptController, its native
supervision/control layer, and shared delivery. SECS continues to own input
interpretation, Upload selection and reading, scientific preparation, model
execution, offerings, result content, and deployment resource policy.

The purpose is to remove a second implementation of START uncertainty, Attempt
observation, lifecycle progress, terminal handoff, native retirement, and result
publication. The final runtime has one owner for each of these responsibilities.
Keeping ExecutionLoop and its journal as a parallel recovery engine would not
complete this redesign.

The existing execution path works and contains important scientific behavior.
Adoption is worthwhile only if that behavior survives and the displaced generic
machinery is removed. This is a substantive migration, not an import substitution.

Finished ownership
------------------

The SECS process selects eligible Jobs and an explicit resource policy. One
shared live claim registry excludes overlapping ownership. Each admitted Job
gets one SECS AnalysisSession and one shared AttemptController. The controller
owns exact START/replay, API point reads, progress, stop decisions, and selection
of the binding's returned outcome for delivery. SECS does not run a second
snapshot/progress loop inside scientific operations.

Acquire ProviderLifetime before API effects, using a canonical private directory
shared by every container that could supervise this provider identity on the
host. A container-private directory cannot exclude a second container. This
lock excludes local supervisors; it stores no recoverable Attempt state.

The session implements prepare, execute, and retire. It owns its actual source
files, interpreter work, scientific requests, and worker lease. Shared native
supervision owns child exit and control-channel retirement. A SECS worker pool
owns model readiness and qualified reuse of an idle loaded model/index.

Each preparing or executing phase passes its shared permission to the native
request. The worker checks it immediately before writing a scientific command;
an interrupted or uncertain request requires original-worker retirement. Warmup
before START is provider-owned and has no Attempt permission. A fresh runner
started during preparation checks the phase before submitting its setup; once
submitted, that setup remains owned even if a later stop is requested.

A received, structurally admitted child failure can produce a public failure.
An unknown worker reply, worker request timeout, or interpretation deadline that
interrupts an in-flight inspection raises the shared unresolved marker during
preparation or execution. When no preparation handle was returned, the
controller has not admitted search; that does not establish a child failure or
completed cleanup.
The controller retains the live claim and does not enqueue FAIL or repeat
science. Independent source and interpretation deadlines retain their reviewed
public outcomes when no worker request is in flight. This live ownership is not
reconstructed after process restart; the server owns Attempt expiry.
Worker request timeouts use this conservative hold even if the local deadline
expired before the frame was written; no separate pre-dispatch outcome is issued.

One shared delivery binding for the API-origin/provider-ref pair accepts exact
complete/fail bodies. The delivery service owns the persistent queue, publication,
retry pacing, and held-report operator state. SECS retains the exact outcome
until its matching durable local acknowledgement. That acknowledgement does not
establish API acceptance. No SECS journal also publishes the same report.

SECS keeps the mol_from_1h_spectrum_formula offering and the
secs.elucidation.result.v1 result. Input readers, formula rules, index selection,
GPU selection, scientific precision, retrieval budgets, and graph-GA policy
remain SECS responsibilities. Generic SDK code must not acquire those rules.

When the binding's queue is full, retain the controller/report and pause new
scientific admission for that binding until handoff can succeed. Settled GPU
resources can be released independently. Other provider bindings remain isolated.

The supervising scheduler owns that gate, not the now-free GPU slot. Its retry
observer records the blocking controller. Normal completion with
DeliveryAcceptedCheckpoint clears its delivery-pressure blocker. If enqueue was
acknowledged but independent retirement failed, the invocation can raise while
retaining verified delivery_acceptance in its original execution failure. An
explicit disposition may clear only delivery pressure from that evidence; it
must retain cleanup exclusion, the live owner, and lifetime locking. Already
queued bytes must not be called unacknowledged, retried as fresh work, or made
contingent on successful cleanup. Other held/failed owners require explicit
resolution, not timer-based resume. That report's acknowledgement
does not reserve future queue space: each new admission still needs its own
live terminal reservation and may meet backpressure again. Do not use an empty
inventory or successful status read as a substitute for that handoff proof.

Make preparation a real boundary
--------------------------------

Today run_analysis interleaves interpretation, bounded inspection, acquisition,
and worker analyse calls. An input_rejected reply returns to interpretation.
ScientificHandler._analyse both prepares the selected spectrum and launches
elucidation. Wrapping this entire loop in execute would conceal the boundary
between choosing valid input and beginning a scientific calculation.

Split the scientific worker operation at input_adapter.prepare and formula
admission. A prepare operation materializes and validates the selected input,
then returns a handle to worker-owned prepared state. The handle is bound to
the worker boot, Attempt, and exact selection/source facts; it is not permission
to read changed files later. Execute consumes that handle once and creates a
fresh graph-GA search using the existing scientific implementation.

SECS AnalysisSession.prepare performs the following work:

1. Accept the controller's verified specification and actual START acknowledgement.
   Acquire Upload membership/capabilities on separately owned API transport.
2. Run the existing bounded interpretation conversation. Preserve inspection
   facts, reader/formula rejections, attributed explanations, and deadlines.
3. Download selected Uploads with length/hash verification and aggregate byte
   accounting. Reconcile membership before scientific dispatch as today.
4. Ask the worker to prepare the selected source and formula. A proven input
   rejection may return to the same conversation before execution begins.
5. Return PreparedAnalysis whose protected identity describes the actual admitted
   selection, verified source identities, and prepared worker state. Retain the
   worker handle and live resources in this session, not in the SDK registry.

An inability to choose usable input returns the existing SECS-classified
AnalysisFailure with its attributed explanation. It does not become success.
Execute consumes the precise prepared handle, returns the existing analysed
result, or maps no_starting_candidates to the existing failed outcome. It does
not reinterpret inputs after an indeterminate scientific dispatch. Unexpected
model or transport failures do not authorize another calculation.

This split must be proved at the actual worker boundary. Moving a flag or hashing
an unvalidated selection is insufficient. If parsing or normalization is repeated
at execution, prove it uses the same immutable state rather than changed sources.

Async execution, readiness, and warm reuse
-----------------------------------------

The current worker/API/interpreter flow is blocking. The new async session must
yield while those operations run so the controller can continue observing the
Attempt. An executor thread is an implementation option, not evidence of stopped
work: retain and join its original operation, signal the actual worker, and
confirm settlement before releasing the lease or source files. Cancellation of
an asyncio wrapper alone cannot establish any of those facts.

Keep one scientific worker slot initially. The SDK's live bookkeeping capacity
is a separate resource allowance and does not authorize eight GPU calculations.
Preserve readiness before START and keep the model/index loaded across healthy
Attempts. A provider-owned pool creates a per-Attempt lease only for a ready
worker. Failed START must still release that lease through session retirement.

Adopt provider_core.runner with an owner-session lifetime for the loaded child,
and provider_core.runner_session.RunnerSession for its control channel. Adapt
the scientific child entry point to the inherited science/lease descriptors;
keep the SECS scientific messages and model/index loading in SECS. Remove the
displaced generic fork/relay/reap owner, rather than nesting two supervisors.

Successful scientific replies need an explicit quiescence rule: the operation
has returned, no child work is still using its inputs, prepared state is consumed
or released, and per-Attempt source access can be released. Only then may retire
return and the pool reuse the worker. A healthy loaded child need not exit after
every Attempt. On interruption or uncertain quiescence, stop the child and obtain
native retirement/scratch confirmation instead. Preserve files and block that
worker slot when confirmation fails.

The following scientific lease protocol is part of the required SECS change;
it is not already provided by the SDK. One RunnerSession.operation and its
scratch directory cover the loaded child's lifetime, possibly many Attempts.
They must never be used as if they uniquely identified one Attempt.

The pool is the sole owner of that native control session and science stream.
It serializes checkout, dispatch, release, and exit handling. Each checkout has
an unguessable lease identity distinct from the Attempt and native operation.
Scientific frames carry the worker boot, lease, Attempt, request sequence, and
prepared-handle identity where applicable. The child acknowledges lease/phase
entry before dependent scientific work. Only the corresponding live session
may consume its responses. Reject stale, duplicate, wrong-boot, and wrong-lease
frames; do not let a later session drain or reinterpret an earlier reply.

Before checkout can change owners, a correlated release reply must establish
that the previous request ended, its tasks joined, and all prepared state and
source readers were cleared. Join the provider-side original exchange too.
The release acknowledgement may be the final scientific reply if cleanup has
already completed before sending it; do not add another round trip merely to
rename the same proof.
The pool then invalidates that handle/lease and admits the next lease only
after a fresh correlated readiness/lease-entry exchange. A missing release,
unreadable stream, or unmatched reply invalidates the child for reuse.

An exit with no active lease is an idle worker failure: replace the child after
settlement, without failing a completed or newly selected Attempt. Before the
new lease's entry acknowledgement, an observed exit does not prove the child
entered that lease's scientific phase. Do not borrow the old lease's evidence
for it. After a matching entry acknowledgement, the original native exit may
be associated with that live lease/phase, subject to SDK admission. That records
where work stopped; it does not prove that this Attempt caused the process to die.

SourceAccess passes filesystem paths, so clearing a mapping or unlinking a file
cannot revoke an open descriptor or erase bytes already materialized in the
worker. A release reply is cooperative evidence from the trusted worker: all
readers/archive handles and per-Attempt prepared data are closed/released, and
no background task can still use them. Remove that Attempt's source directory
only after this protocol and the provider's readers settle. Do not describe
this as kernel-enforced per-Attempt revocation. Where that cooperation is not
established, terminate/reap the child before releasing the sources. Forced
revocation within a still-live warm child is outside the current design.

Use a separate API transport for source acquisition and another for Hello;
neither shares the controller's serial transport while observation is active.
Keep SECS's closed-Job policy by allowing open and closed states; cancelled Jobs
stop work. Preserve aggregate preparation/scientific deadlines explicitly.

Crash reports, transparency, and restart
----------------------------------------

The intended policy changes notes/004's restart-interruption behavior. Bookkeeping
is live-only. A new supervisor does not replay old START state, resume preparation,
poll old Attempts, or manufacture interrupted failures from a missing owner.
The server continues to own terminal expiry under its policy. Reports already
accepted by shared delivery continue independently after SECS exits.

This also replaces the old unconditional failure synthesis in ProviderStopping
and AnalysisCancelled handlers. Shutdown, cancellation, or expiry follows the
controller's stop/publication permission; SECS must not catch a stopped execution
and force another FAIL through its old API client. Expected scientific inability
remains explicitly classified by SECS. Unexpected exceptions retain their causes
and cleanup state instead of automatically becoming invalid-input failures.

An unexpected original worker exit observed by the live owner may become
ObservedWorkerCrash only with its current Attempt, phase, SDK RunnerSession,
and original native exit evidence. EOF, timeout, a deliberate stop, or a killed
worker is not enough. Record local interruption before closing channels or
requesting stop. On unexpected EOF, observe original retirement within a bounded
wait before deliberate close; retain the original reader if that wait expires.

Distinguish expiry of a caller's wait from failure of the lifecycle read itself.
If the original read is still running, keep and join that same operation; never
start another reader. If RunnerSession's own read raises, including its timeout
after a partial frame, it stores _observation_failure and refuses later reads.
The original object then preserves a failure, not a resumable frame reader.
A later child exit cannot repair that channel or establish original_exit through
a second observation. Process exit and scratch cleanup are separate facts.

The current SDK has no in-process reset for this poisoned channel. Mark local
interruption, request stop through the original native owner where possible,
retain sources, and expose an unconfirmed-retirement state that blocks this
slot. Health/status snapshots or absence of a socket do not clear it. Do not
introduce another supervisor or synthesize a retirement receipt to regain capacity.

The recovery path is explicit offline containment: stop admission, preserve any
live unacknowledged report, and attempt its original handoff first. If ownership
still cannot settle, an operator may authorize emergency stopping of the affected
provider and exact runner deployment. Confirm that its original supervisor and
child processes are gone through the deployment owner, then inspect and clean
the exact retained operation/source directories under exclusive ownership.
Verify scratch cleanup independently before restarting a fresh native session.
This retires an unconfirmed lifetime; it does not repair its SDK object, fabricate
a crash report, or reconstruct an Attempt on restart. Emergency provider death
may lose an unacknowledged report and must disclose that consequence. Qualify
this recovery procedure before rollout; the current status protocol is not
evidence that it is already implemented.

The current SECS WorkerClient is not an SDK RunnerSession and cannot be cast or
wrapped by name to manufacture this evidence. Shared native control adoption is
part of this design, not an optional promise to fill the gap after rollout.

Preserve maximum useful, non-sensitive explanations and correlated diagnostics.
The failure endpoint cannot carry the full cannot_analyse or empty-retrieval
report, so retain that evidence through a separately owned diagnostic/report
store. Diagnostic history does not authorize execution, replay, or publication.
Its write failure remains visible and must not veto an otherwise admitted crash
report or replace a chosen outcome. Do not retain a hidden executable journal
under the name of diagnostic history.

For ordinary reports, SDK 0.4.0 still lets a failing retry observer stop handoff;
only admitted-crash retry observers have core protection. The SECS observer
must keep semantic admission/backpressure state separate from diagnostic I/O,
retain a bounded sink failure in operator-visible state, and not propagate that
diagnostic failure back into a chosen report's handoff. Do not silently swallow
it or misclassify an ownership failure as a harmless logging error. Qualify this
consumer callback behavior for both selected success and classified failure;
the design does not assume a broader SDK guarantee than the source provides.

Durability begins when shared delivery commits the exact report. If SECS dies
before it can confirm handoff, acceptance may be unknown and the report may be
lost; restart does not reconstruct it. This is an intentional policy change and
must be stated in operator guidance, not described as equivalent recovery.

Deployment and old obligations
-----------------------------

Separate stopping new admission from setting the controllers' stopping event.
A scientific outcome being returned is not yet a selected terminal handoff:
_handoff checks require_execution_ready before selection. If stopping wins that
race, the controller can refuse selection. Do not promise that every returned
outcome drains on orderly stop. Already selected/approved handoffs retain their
original exact retry owner; unselected outcomes stopped by controller policy
need settled original work/I/O followed by the SDK's explicit supported
suppression disposition where applicable. Record the reason; never send them
through an alternate publisher or mark them enqueued. A selected report cannot
be erased using the unselected-outcome suppression path. Other unresolved
outcomes remain held. Shutdown readiness requires each owner's actual valid
delivery/suppression disposition and independent cleanup, not a fabricated ACK.

On orderly shutdown, stop admission and settle the original controller, API,
delivery, and native operations. work_settled alone is insufficient: an outcome
still awaiting durable handoff can block shutdown_ready. Hold ProviderLifetime
until all controllers are shutdown-ready and the other resource owners settle.
Forced death does not acquire orderly shutdown guarantees by deleting state.

The normal stop sequence is: stop admission; settle/stop science; release settled
GPU resources; keep each exact selected handoff and its retry owner alive; wait
for matching durable enqueue and all required cleanup; then release the lifetime
lock and exit. Use the SDK's supported settlement path rather than cancelling
the handoff task as a substitute for draining. Surface blocked shutdown with
its Attempt/report identities, delivery state, and independent cleanup failures.

If delivery never becomes available, this wait has no guaranteed finite bound.
A generic service stop timeout must not silently be the normal report-loss policy.
Deployment shutdown tooling must observe and escalate a blocked drain before
automatic kill, and allow the operator to restore delivery. An explicit emergency
force-stop decision can accept loss of an unacknowledged report; it is separate
from successful orderly shutdown and creates no restart recovery promise.

Use the shared neutral binding definition for API identity, signing credential,
CA, route, and delivery socket. Provider and service select the same binding;
SECS keeps scientific configuration and interpreter credentials separately.
Mount the binding's IPC volume at the socket's parent in the provider and grant
its socket group. Keep the queue in its service-owned persistent volume.
An API outage must not require loading SECS or keeping the GPU occupied merely
to publish a previously acknowledged queue item.

Do not silently reinterpret existing AttemptStore records as live SDK owners.
Before switching a deployment, stop admission and use the old qualified runtime
to settle retained START/active/terminal obligations under their existing policy.
Check and record the journal state while its exclusive owner is stopped. If an
obligation remains held or uncertain, block cutover and preserve it for explicit
operator resolution. Do not delete it, issue a replacement key, or change its
terminal bytes. Read-only evidence can be archived after its obligations end.

While a live START is uncertain, retain its exact key/body; do not generate a
replacement to bypass the uncertainty. Keep active START replay execution disabled.
An already-active receipt identifies an Attempt, not whether science ran.

This design chooses an empty-obligation cutover, not a permanent dual reader or
an unqualified queue importer. Existing diagnostic/report files need not be
deleted to obtain an empty obligation set. No running worker or shared queue
volume is retired merely to make migration checks pass.

Remove the displaced ExecutionLoop, active/start journal recovery, direct terminal
publisher, duplicate lifecycle observation, and generic worker supervisor from
the new runtime after their consumers move. Replace journal-inspection commands
with clearly separate diagnostic-history and shared-delivery operations. Update
notes/004 and 006's operational guidance when implementation lands; retain their
historical evidence with an explicit supersession pointer.

Why objections do not change the end state
------------------------------------------

"The current journal survives crashes." It does; the new live-only controller
deliberately has a different restart contract. Do not claim equivalent durability
or rebuild the old recovery controller beside it. A requirement to retain that
contract would require revisiting the adoption decision before implementation.

"Our scientific input loop is special." Keep it in SECS. Change its worker seam
so input rejection is resolved before the exact scientific dispatch; do not move
SECS readers or formula policy into the SDK to avoid writing the adapter.

"Retirement would reload a costly model." Per-Attempt quiescence and loaded-child
exit are different. Keep qualified warm reuse, but prove it rather than treating
a closed socket or a completed Python wrapper as proof.

"A delivery service adds operations." It adds a service and socket grant, and
removes publication/retry responsibility from the scientific process. Recreating
a local outbox or publisher would cancel that ownership simplification.


The admitted-crash path catches ANY retry-observer exception, including a
semantic admission-gate failure. Raising that exception alone cannot enforce
fail-closed scheduling. Before a semantic gate update, latch a separate visible
intervention/admission-block marker; clear that provisional marker only after
the semantic update succeeds. On failure, preserve its cause and leave the
marker set independently of whether the SDK catches the exception. Admission
always checks this marker. Diagnostic-sink isolation must not clear it; operator
recovery needs an explicit validated gate/owner disposition. Protecting crash
handoff must not silently reopen scientific admission after scheduler failure.

Report and evidence budgets
---------------------------

Configure explicit live-control, terminal-body, queue-count, and queue-byte
allowances. The SDK caps a controller's terminal reservation at 2,097,152 bytes;
raising a SECS configuration value cannot enlarge that ceiling. The bound applies
to the fully encoded complete/fail request, including its envelope, not only
the scientific content or separately stored diagnostic evidence.

Before rollout, bound the actual encoder using the supported candidate counts,
selection/rejection histories, text lengths, and scientific metadata. Verify the
worst supported configuration fits the ceiling, and reject configurations that
cannot satisfy that bound before admitting science. If required scientific
content does not fit, obtain a deliberately revised and qualified SDK/wire
contract before adoption; this note does not authorize one.

Unexpected oversize after computation is a held software/contract failure. Stop
new admission, retain the exact outcome and cleanup owner, release only settled
scientific resources, and expose the attempted encoded size and fixed ceiling.
Do not truncate, rerun science, or replace that result with a convenient FAIL.
The current controller cannot enqueue it or become shutdown-ready by increasing
its allowance. Operator/developer resolution must preserve the outcome and
explicitly address any emergency loss risk; ordinary restart is not a remedy.
Keep diagnostic-history budgets separate from these required report bytes.

Completion and evidence required
--------------------------------

Before merge, prove the actual SECS binding, not only SDK fixtures:

- Race stopping with scientific return before terminal selection, then with an
  already selected handoff. Prove supported explicit suppression versus exact
  draining; neither path invents delivery or cleanup acceptance.
- Inject durable enqueue ACK followed by independent retirement failure. Clear
  delivery pressure only from retained verified acceptance, preserve cleanup
  exclusion, and never resend already queued bytes as a replacement report.
- Fail the semantic gate update during admitted-crash retry. Even if the SDK
  catches the callback exception and handoff continues, admission stays latched
  closed and the semantic failure remains visible for explicit intervention.

- Reader/formula rejection returns to interpretation before one consumed prepare
  handle leads to at most one search. Membership changes cannot substitute input.
- Existing scientific outputs, unsuccessful outcome classification, decimal-string
  encoding, and useful selection/diagnostic evidence remain intact.
- API observation runs during blocking preparation/search. Closed Jobs continue,
  cancellation stops, and API observation outages follow an explicit bounded policy.
- Known worker exit and deliberate interruption remain distinguishable. Failed
  stop/cleanup keeps sources and worker exclusion; healthy reuse avoids reload.
- Delay old scientific replies past release, inject wrong lease/sequence, and
  kill an idle child between leases. No reply or exit is attributed to a new
  Attempt without its own entry/phase evidence. Prove the worker really closes
  per-Attempt readers/prepared state before a cooperative release acknowledgement.
- Exercise a caller wait expiring around a still-running original read separately
  from a lifecycle read that fails on a partial frame. Subsequent native exit
  does not clear a poisoned read or prove scratch cleanup. Rehearse the offline
  containment procedure and refuse reuse before all its proof obligations hold.
- Keep delivery unavailable throughout shutdown: settled GPU work releases, exact
  report retry and lifetime exclusion remain, and blocked drain is visible. Test
  the supported encoded maximum and an unexpected oversize outcome without
  truncation, recomputation, replacement failure, or a false shutdown-ready state.
- Lost enqueue acknowledgement retries identical bytes while the live owner remains;
  queue-full backpressure releases settled scientific resources without losing
  the report. A chosen report and independent cleanup failure both remain visible.
- After durable enqueue, SECS death does not stop publication. Before handoff,
  supervisor death causes no restart-generated START, FAIL, or calculation.
- Upgrade refuses a nonempty legacy obligation set. Shared queue identity,
  credential/socket permissions, and provider isolation survive the cutover.
- The new runtime has no reachable legacy controller, publisher, recovery reader,
  or second native supervisor. Change an ordinary SECS reader without editing
  SDK lifecycle code, and exercise that change through the same session contract.

Contained adapter tests, installed deployment tests, real worker/model checks,
and signed API acceptance are distinct proofs. Run the relevant maintained lanes
for the implementation and name what each establishes. This note runs none of
them and authorizes no production rollout.
